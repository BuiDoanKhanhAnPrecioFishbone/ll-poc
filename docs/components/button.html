Button

src/ui/Button.tsx · specimen at /design-system
Model page. This is the template every other component page should follow. The order of the sections is the order a reader needs them in, and it is the order Carbon, Atlassian and GOV.UK all arrive at: what it is for, when not to use it, what it is made of, how it behaves, what it costs a screen reader, and only then the API.

When to use

A button performs an action on this screen: save, export, confirm, add a line, run the quotation.

When not to use

Instead of a buttonUseWhy
Navigating to another screenA link, or Button asChild wrapping a router LinkA destination must be a real anchor: middle-click, copy-link and the browser's own back behaviour all depend on it
More than four actions in one toolbarFour buttons and More ▾D1. The limit is what keeps the primary action findable
A destructive action in the openMore ▾, then a confirm dialogDelete, deactivate and reverse sit behind the menu; the dialog is where danger appears
A choice between optionsRadio, select, or a segmented controlA row of buttons that set a value reads as five actions, not one question
Toggling something on and offA checkbox or switchA button does not carry state a user can read

Anatomy

PartRule
1Container--vy-shape-full. Height comes from the size rung, never from padding. A 1px transparent border so outlined and filled measure the same
2Icon slotOptional. aria-hidden — except while busy, when it holds the indicator and carries the only machine-readable statement that the action is running
3Label--vy-text-base at --vy-weight-medium, Title Case (B2), white-space: nowrap

An icon with no label makes the button square: k-icon-button gives the box equal padding on both axes and floors the glyph at one line box, so width and height arrive at the same number out of the size scale.

Variants

The ladder is Material 3's, and it encodes emphasis, not colour.

VariantWhenIn the build
filledOne per view. The most likely next step46 call sites
outlinedThe default for everything else — and the value you get if you pass no variant10 explicit, 41 implicit
textTertiary, inside dense rows18
tonalA secondary action that still needs weight7
dangerDestructive — and it goes behind More ▾6
tonal is the one rung Kendo does not have. MD3's tonal is a filled button at low emphasis — a tinted surface with dark text — and Kendo's ladder goes straight from solid to transparent flat. It takes Kendo's solid structure and our tint. flat was tried first and could not work: .k-button-flat sets background: initial !important, which no specificity beats. This is the one place the component paints over Kendo, and it is deliberate.

States

Three of these cannot be photographed. A specimen that fakes them photographs a rule the product never runs — putting .k-hover on a tonal button turns it solid primary, while a real pointer leaves it tinted — so the specimen above draws the three that hold still and the rest are written down here, with the token that drives them.

StateWhat happensToken
Default——
HoverA translucent layer over the base colour, via ::before. tonal additionally deepens its tint--vy-state-hover: .08, and --vy-brand-subtle-strong for tonal
FocusKeyboard only — :focus-visible, so a mouse click leaves no ring. 2px outline, offset 2px--vy-brand-boundary

BusyIndicator in the icon slot, and the button is disabled—

busy is two things, and the disable is the load-bearing half. The indicator says something is happening; the disable is what stops a second click spending a second marketplace request. The loader replaces the icon rather than sitting beside the label, so the button keeps its width and nothing in the toolbar moves when the action starts. It pulses rather than spins: the dots hold still, so the control does not appear to rotate.

The indicator takes the on- colour of the fill it sits on. Found while writing this page: it used to take Kendo's base theme colour, #3d3d3d, on the two solid variants — 1.19:1 against --vy-brand and 1.97:1 against --vy-danger, where WCAG 1.4.11 asks 3:1 of an indicator that carries meaning. The two it failed on were the primary action and the destructive one.

themeColor could not fix it: Kendo's Loader accepts only base | primary | secondary | tertiary, and none of them is light. So the colour comes from the token that already exists for the job — the on- half of the fill's own pair.

Using the paired token instead of a loose colour did not just fix the ratio — it put the indicator inside a check that already runs on every push. That is the argument for pairing every surface with its on-.

Content

  • Title Case, and the label names the outcome: Publish, not OK. Publish then produces a toast reading Published (D6).
  • Never "Cancel" outside a dialog. In edit mode the word is Discard Changes. In a confirm dialog the safe button names what the user keeps — Keep Order, Keep Editing — so Cancel · Cancel Order can never read as two cancels.
  • Labels do not wrap and do not truncate; if a label needs more room, the label is too long.

Behaviour

  • Placement: all buttons on the left of a toolbar; a smart-button group or step indicator on the right. At most four visible, the rest behind More ▾ — and the label is always the word More with a chevron, never ⋯.
  • Keyboard: Enter and Space activate, as for any <button>. Focus order follows the DOM; the toolbar is before the record.
  • asChild renders the styling onto a child element — a router Link — so navigation stays a real anchor. It is the one path that does not go through Kendo, which is why a.vy-btn has to cancel the underline by hand: without it a line runs through the middle of a filled pill.

Accessibility

Icon-onlyNeeds aria-label. The glyph is aria-hidden, so without one the button has no accessible name. 97 aria-label call sites in the build
Busyaria-busy="true" on the button; the loader carries role="status" and aria-label="Working", so it is announced without interrupting
DisabledA disabled button leaves the tab order. Where the user needs to know why, the reason belongs in a tooltip or beside the control, not in the button
Focus:focus-visible only — a ring for the keyboard, nothing on a mouse click
Target sizesm carries min-height to clear the 24px minimum (WCAG 2.5.8); padding alone left the pager one pixel short. xs clears it at 26px unaided

ref is destructured out of the spread on purpose. In React 19 ref is an ordinary prop, so Popover.Trigger asChild injects its ref and the spread handed it to Kendo — whose useImperativeHandle exposes { element, selected }, not a node. Radix measured that object and re-measured it forever: every page rendered nothing, with "Maximum update depth exceeded". The fix is to unwrap Kendo's handle to the node underneath, because a DOM node is what this component's contract promises. disabled is destructured out for the same kind of reason. Written above the spread, {...rest} put its own disabled={false} back on top and the busy button stayed clickable — measured on Get Prices, the one button in this product where a second click costs money.

Gotcha worth knowing

.vy-btn--filled, --outlined, --text and --danger in components.css apply only on the asChild path. A normal button goes through Kendo and carries Kendo's classes alone, so those rules never match it. Only .vy-btn--tonal is passed through to the Kendo element. Styling a variant by editing .vy-btn--outlined and seeing nothing change is this, not a specificity problem.
