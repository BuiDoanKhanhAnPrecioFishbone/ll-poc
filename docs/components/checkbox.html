Checkbox

src/ui/Overlays.tsx · a native input wearing Kendo's classes, and that is the interesting part.

When to use

A single yes/no, or one of several independent yes/nos: Conformal Coating, Provide Alt AML For Out of Stock, a column in the column chooser, a row in a grid.

When not to use

Instead of a checkboxUseWhy
One choice among severalRadio groupCheckboxes are independent; radios are exclusive
A setting that applies immediately and can be undoneA switch — which this app does not haveThe live system uses k-switch ×4 and nothing here matches it yet
Filtering a listChip or the filter toolbar

Why the class, not Kendo's React component

Kendo's <Checkbox> cannot express two things this app needs:

indeterminate. There is no prop for it. The grid's select-all box needs it to mean "some rows on this page, not all", and it has to be set through the DOM node either way.

aria-label. Only ariaLabelledBy / ariaDescribedBy are offered — and the grid names every row's box individually:

"Select 01455-387-9552", because a screen reader moving down twenty identical labels reading "Select row" learns nothing.

Kendo's component renders exactly this markup anyway: a native input carrying k-checkbox. Using the class directly gives the same pixels, keeps both capabilities, and avoids a React wrapper around each of the ~300 checkboxes a full grid page renders.

Kendo styles .k-checkbox:indeterminate — the native pseudo-class — so the state comes through with no help from us.

k-checkbox-lg, and why the size is not a detail

20px, measured — exactly the size the hand-written box was.

md is 16px and would have quietly shrunk every checkbox in the app by a fifth, including the grid's, where the label's 24px target is switched off and **the box is the pointer target**.

Two Kendo defaults the bridge has to correct

Kendo's defaultHere
Unchecked boundary--kendo-color-border → grey-200, 1.30:1--vy-border-control
Indeterminate boxA white box with a blue dash — the dash reads at 5.9:1, but the outline still came from the global borderSame visible edge as an empty box
DisabledStyled by class, so a plain <input disabled> renders identically to an enabled oneKeyed off :disabled, dimmed by --vy-state-disabled
An indeterminate box is not a checked one. It needs the same visible boundary as an empty one, which is why the rule is :not(:checked) and not :not(:checked):not(:indeterminate) — the first attempt left the select-all header with the faint edge the rule was written to fix.

Disabled uses opacity, not a grey wash. The earlier rule put :disabled after :checked at equal specificity, so a disabled ticked box went grey and took its white tick with it — on exactly the control whose whole job was to show "this column is always shown".
