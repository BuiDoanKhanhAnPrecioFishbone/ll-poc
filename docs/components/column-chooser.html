Column chooser

src/ui/ColumnChooser.tsx · 5 call sites.

When to use

On every grid with three or more columns (D3), to let a user turn columns on and off for themselves.

When not to use

Instead of the column chooserUseWhy
Changing what every user seesView SettingThe chooser is one person's view of one grid. A View is a shared, saved definition
A grid with one or two columnsNothingThere is nothing to choose between
Hiding a column nobody should ever seeLeave it out of the gridA column in the list says it exists; if it must not exist, it must not be listed
Reordering columnsNot supportedOrder comes from the grid definition

What it replaced, and why

A "Show 2 more columns" button, which the 25 August review flagged as a confusing label and asked to become a checklist. Three problems, only one of them the wording:

  1. It named its effect on one particular state, so it read as a different control depending on what was already on.
  2. It had two states only — the shipped set, or the shipped set plus everything. Wanting one extra column meant taking all of them, and a column you never use could not be turned off.
  3. It hid the existence of the extra columns behind a count.

A checklist has none of those, and it shows what is available.

Anatomy

PartRule
TriggerA sm Button. outlined normally; tonal once any column is hidden, so a grid that is not showing everything says so from the toolbar
LabelColumns, and Columns (5/11) when some are off — shown over total
Popoveralign="end", 6px offset, with an arrow
HeadColumns and a text Button reading Reset
RowA k-checkbox-lg, the column title, and — where it applies — always shown and a note

A required column shows as ticked and disabled, not absent. Otherwise its row is missing from a list that claims to be every column, and the user wonders where it went.

Measured on Project Requirements: 11 columns, 6 of them required. Every required row is both ticked and disabled — verified, not assumed. It is worth knowing that more than half this particular list cannot be changed; a chooser where most rows are fixed is closer to an inventory than a choice, and if that ratio grows the control is the wrong one.

States

StateWhat happens
All columns onTrigger is outlined, label reads Columns
Some hiddenTrigger is tonal, label reads Columns (n/total)
Required rowTicked, disabled, always shown beside it
Disabled checkboxDimmed by --vy-state-disabled, not greyed by a fill — a grey wash took the white tick with it, on exactly the control whose job is to say "this column is always shown"

Content

  • Reset, not Restore defaults — it is one word for one action, inside a popover that is already titled.
  • A column that ships hidden carries a note saying why, so a reviewer does not have to ask.
  • always shown is lower case and quiet; it is a fact about the row, not a second label.

Behaviour

  • Toggling applies immediately; there is no OK button.
  • The popover closes on Esc and on a click outside — and Esc closes the innermost thing first (D4).
  • The trigger carries .vy-columns-btn purely as a layout hook: below 820px the toolbar moves it onto the search row so the view picker is not squeezed to Def…. There was nothing else to select it by.

Accessibility

CheckboxA real <input type="checkbox">. Kendo styles it; the bridge gives the unchecked box its --vy-border-control edge, because Kendo's default was 1.30:1
DisabledKendo styles disabled by class, so a plain disabled attribute renders identically to an enabled box. The bridge keys off :disabled for exactly this control
IndeterminateThe select-all header box is white with a blue dash; the dash carries the state at 5.9:1, and the bridge gives the box the same visible edge as an empty one
PopoverFocus moves into it; Esc returns focus to the trigger
