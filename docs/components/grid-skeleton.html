Grid skeleton

src/ui/GridSkeleton.tsx · the first-load state of the standard list pattern.

When to use

A first load, where nothing is on screen yet. The route has resolved, the rows have not arrived, and the user is looking at the screen they asked for.

When not to use

Instead of a skeletonUseWhy
Work over rows already on screenBusyOverlay"What will this look like?" is already answered
A list with no rows to showThe empty stateA skeleton promises rows that are coming
A failed loadThe error stateA skeleton that never resolves is the worst of the four states

The cells are proportioned by column role

It takes the real ColumnSpec[] and sets data-role on each cell, so the placeholder reads as the same shape of table that is coming.

data-roleShare of the row
ident18%
text22%, and the only flexible one
date11%
money9%
status · rating9%
code · number7%
They approximate rather than match exactly. The real widths are numbers in the token layer, and reproducing them here would mean an inline style per cell — a second copy of the width table, kept in step by hand.

A skeleton whose bars are all the same width tells you a table is coming. One whose bars follow the roles tells you which table.

What the live system does instead

The customer's build renders "No records available" while its spinner is still turning — audit finding T5.

For the first moment of every list screen, the product says there is nothing there. Then the rows appear. The empty state and the loading state were wired to the same condition.

Loading and empty are two different answers, and only one of them is true at a time.

aria-busyStays on the container until the real rows replace it
