People picker

src/ui/PeoplePicker.tsx · Assigned To, and every other field that names colleagues.

When to use

To choose one or more people from the directory.

When not to use

Instead of a people pickerUseWhy
A list of codes or statusesSelectPeople need a face and an address; a status needs neither
A free-text nameNothing — don'tA typed name cannot be assigned to

It replaced a single-value dropdown, which was wrong twice

Built from the live control An sent on 31 Aug 2026 and confirmed in the bundle: component: "MultiSelect", with tagRender and onTagDelete for the chips and options carrying an avatar.

Our Assigned To was a single-value dropdown of bare names — one value where the live system takes several, and a name where it shows a face and an address.

The email is not decoration

The live directory holds "Linh 4 Tran", "Linh Tran 5" and "Linh Tran 1". Ours has Linh Tran and Toan Dinh, whose initials collide at a glance.

A directory of colleagues is precisely where names repeat, and the email is the line that tells two of them apart. The avatar is what makes the row scannable once you already know which one you want.

So the row is avatar · name · email, and the filter matches both fields, contains and case-insensitive, as the live filter descriptor does — someone who knows the address rather than the spelling of the name should not have to guess.

On Popover, not Select

Radix Select holds options and manages focus for a listbox. It cannot express multiple values, and its focus scope is the thing that stopped Select's own filter box taking focus.

Popover has no such scope, so the filter input here is focusable and typing goes to it immediately — the way the live filterable control behaves.

Accessibility

Avatararia-hidden — and initials, not an image. The live options carry avatar photographs; this prototype has none, and inventing them would put fictional faces on a colleague list

FilterReachable and focused, which is the reason for Popover
