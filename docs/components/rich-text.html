Rich text

Status: trial · src/ui/RichText.tsx · the Conversations tab. Trial, because the implementation is deliberately provisional — see below. Written to the template set by button.md.

When to use

Where a comment written in the real system can arrive formatted — the Conversations tab, and nowhere else yet.

When not to use

Instead of rich textUseWhy
A description or note fieldA textarea — see FieldFormatting someone cannot see elsewhere is formatting lost
A single lineAn input
A plain textarea here would render a formatted note as a wall of unstyled text, and an editor missing Clean formatting cannot undo a paste from Word. Those two facts are why this component exists.

The toolbar is the live one, in its order

`` Undo · Redo | Bold · Italic · Underline · Strikethrough | Unordered list · Ordered list | Color · Background color | Outdent · Indent | Format | Clean formatting ``

Read off the live editor and reproduced exactly, because a comment in the real system can contain all of it.

The glyphs are drawn, not lettered — B/I/U as paths rather than characters, so the toolbar does not depend on the UI font.

Two places it narrows the live control on purpose

LiveHereWhy
Text colourKendo's full spectrum5 system ink coloursIn a comment thread a wheel is more freedom than anyone needs and a reliable way to produce unreadable text on white
HighlightFull spectrum4, including NoneSame, and all four are grounds the ink above stays legible on

What is deliberately not built

The live tab shows a "?" beside the toolbar. It looks like a help control.

It is not. It is the current user's avatar with no initials to show. Worth recording, because building a help affordance that does not exist is exactly the kind of invention this project has had to keep undoing.

Implementation, and why it is trial

contentEditable plus document.execCommand.

execCommand is deprecated, and its replacement is to ship a full editor framework — a large dependency to prove a small point in a prototype. It is supported in every current browser, and the seam is one file: swapping in a real editor later means replacing this component, not its callers.

That is the whole reason for the trial status. The surface is right; the engine is provisional.

Accessibility

Toolbarrole="toolbar"; every button has a text label, never the glyph alone
Pressed statearia-pressed on the mark buttons; Undo/Redo are stateless and carry none, because they have no on/off to reflect
The surfaceLabelled, and reachable with one Tab from the toolbar
KeyboardThe browser's own Cmd/Ctrl+B/I/U work, because the surface is a real editable region
Colour menusEach swatch is named — Red, Amber — not colour alone
