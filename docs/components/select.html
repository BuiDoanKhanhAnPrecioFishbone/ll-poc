Select

Status: stable · src/ui/Overlays.tsx · 39 call sites. Written to the template set by button.md.

It is a combobox: the field is the input, and the list filters as you type.

When to use

To choose one value from a list the system owns — a customer, a project type, a saved view, a supplier.

When not to use

On/offCheckbox

It will not accept a value outside the list

Kendo's allowCustom permits that; this does not.

bundle-evidence.md established that Customer is a lookup. Typing a customer who does not exist has to be impossible. Type to narrow, then choose.

That is the single rule that separates this control from a text field, and it is why the two are not interchangeable even though they look similar.

Why it was rebuilt on Popover

It was Radix Select with a filter box inside the content. Two problems, which turned out to be the same problem.

Focus. The filter box could never hold focus — Select keeps a focus scope on its listbox and returns focus to the selected option. autoFocus, a frame later and a macrotask later were all beaten. Popover has no such scope.

Shape. Checking the live bundle settled what it should have been anyway: onComboBoxKeyDown appears in the app's own code, and the ComboBox implementation ships. A combobox's trigger is the text input — you type in the field, as the live Assigned To control does, not in a box that appears after opening a button.

So the filter box was never the right shape. The field itself is.

Options can be a value or a pair

``tsx options={['New', 'Repeat']} // the text IS the value options={views.map(v => ({ value: v.id, label: v.name }))} ``

The pair form exists because of the view pickers. A saved view is chosen by id and shown by name; view names are user-typed with no uniqueness check, so two views may legitimately read My view. Keying the control on the label would make one of them unreachable — a bug the plain <select> this replaced did not have, because it carried value={v.id}.

Size is defaulted, not optional-in-practice

size defaults to medium, and that default is load-bearing.

Kendo's ComboBox emits no size class when given none — the control rendered k-combobox k-input and nothing else — so a scale keyed on k-input-md could not reach it, and the form's select sat at 29px beside a 34px input.

A component that always carries a size name is the whole point of having a scale.

SizeWhere
medium (default)Forms, dialogs
smallGrid toolbars — View picker, Filter toolbar

The footer

Pinned under the option list, inside the popup, for a list that is deliberately short.

Guideline 2.1 §3.3.1 has the Supplier dropdown show preferred suppliers only, with Load more suppliers at the bottom to reach the rest and the brokers. A short list with a way out is a different thing from a truncated list.
