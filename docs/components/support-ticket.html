Support ticket

src/ui/SupportTicket.tsx · the customer's screen of 29 Oct, reached from the error state. Trial, because what stands between it and a real ticket is one POST and the answer to open question 12.

When to use

As the way out of an error **that is not try again**.

A user whose screen fails twice has nowhere to go — and the thing they would otherwise do by hand (find someone, describe what broke, remember which screen it was) is exactly what a program can do for them.

When not to use

Instead of a ticketUseWhy
A recoverable failureTry again on the error stateReload is the right first answer
A feature that does not existtoast.notImplementedThat is not a fault to report

What it attaches, and why that is the point

FieldSource
Error IDnewErrorId(), from the failure
ScreenThe screen that failed, in the user's words
TimefmtDateTime(new Date()) — the app's own regional formatter
BrowserbrowserName()

Those four are what a support engineer needs and what a cost estimator has no reason to know. The one question left is the one only the person can answer — What were you doing?

The block is headed "Added for you" rather than hidden, because a ticket that quietly collects details about the sender is a different thing from one that shows them what it is sending.

browserName() — every browser claims to be the others

Edge's user agent contains Chrome and Safari; Chrome's contains Safari. So the test runs most specific first, and Safari — which claims nothing — is last. Four names, because four is what a support engineer acts on.

newErrorId() — VIQ-7F3A2C

One per failure, so two people reporting the same screen are not reporting the same incident.

Uppercase hex without the vowel-shaped digits, deliberately: this number gets read down a phone line, and 0/O and 1/I are where that goes wrong. crypto.getRandomValues where it exists — two users failing in the same millisecond is not a reason to hand them one id.

The send is not real

There is no helpdesk behind this prototype. The number is drawn here and no request leaves the browser.

The flow is kept whole so it can be demonstrated end to end, and the copy is the customer's own. Written down in three places — this page, the file's header, and the gap register — so nobody demonstrates it as working.
