Tabs

Status: stable · src/ui/Overlays.tsx · 6 call sites, every one of them a record. Written to the template set by button.md.

When to use

To divide one record into sections the user switches between without leaving it: Specific Requirements, Checklists, Quotation Result, Conversations, Activity Logs.

When not to use

Instead of tabsUseWhy
Steps in a job with an orderWizardTabs say these are peers; a stepper says this comes first
Two sections, both shortBoth, stackedA tab that hides four lines costs a click to save nothing
Separate recordsRoutesA tab you cannot link to is a page you cannot come back to
A filterChip or the filter toolbar

Anatomy

PartRule
StripDirectly under the record identity, inside the same panel
TabLabel, plus a count badge where there is something to count
CountOnly when greater than zero — a badge reading 0 is noise with a border
PanelSame surface as the record. Not a card inside a card

The strip sits under the identity, not above it. Switching tab must not cost you the record number — see Record form.

Why this one is wrapped at all

It was chosen as the first Kendo migration because it had the strongest evidence and the smallest surface:

k-tabstrip is the second-most-common marker in the live bundle (×12). These are tabs the customer already looks at every day.

All six call sites go through this wrapper, and the API did not change, so none of them were touched.

Keyed by value, not by index

Ours is keyed by value — 'general', 'quantity'. Kendo's is keyed by index.

Translating here rather than at the call sites keeps tab identity in the caller's own vocabulary:

A reordered tab array would silently change which tab an index selects. A string cannot drift that way.

The unknown-value case is a real difference

Radix showed no panel when value matched no tab. findIndex returns -1, which Kendo treats as none selected and renders an empty strip.

This clamps to the first tab instead, because that is the better failure:

A mistyped value shows the wrong tab, which someone notices — rather than an empty box, which reads as a broken screen.

No current caller can reach it; every one initialises from its own tab list. It is a guard, not a behaviour anyone relies on, and it is written down so the next person does not remove it as dead code.

Content

  • The label is a noun phrase, Title Case: Checklists & Assignment, not View checklists.
  • A count is a number alone — no "items", no parentheses.
  • Tab labels do not wrap. If one needs to, it is too long.

Accessibility

RolesKendo's TabStrip carries tablist / tab / tabpanel
KeyboardArrows move between tabs, Tab moves into the panel
CountInside the tab's label, so it is part of the accessible name — "Checklists & Assignment 4"
IdentityThe record number is outside the tablist, so it is not re-announced on every switch
