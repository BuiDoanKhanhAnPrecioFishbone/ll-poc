View setting

src/ui/ViewSetting.tsx · the panel behind the gear, and the place two other components point at.

When to use

To change the saved View — which filter fields appear, which columns, in what order, sorted how. It is the only place those are edited.

When not to use

Instead of View settingUseWhy
Narrowing this visit's listFilter toolbarA filter is a value; a View is a definition
Hiding a column for yourselfColumn chooserThe chooser is personal and temporary; this is saved and shared
Switching between ViewsView pickerThis edits one; the picker chooses among them

A right sidebar, not a modal

The customer's Testing Guideline says it plainly: display the "Request For Quotation — View Setting" right sidebar".

An earlier note in this file recorded it as a modal — read from a screenshot of it maximised. A screenshot of a thing at its largest is not a description of the thing.

Two copy defects, corrected rather than copied

The live build's Sort tab reuses the Column tab's hint verbatim — it says "Add or remove columns" on a sorting panel — and its add button reads "Add a column".

Both are logged as D5 and D6, and both are corrected here.

A wrong instruction is not a convention worth preserving. The rule in precedence is that the live system governs content and purpose — same fields, same words, same options — and a sentence that describes the wrong panel is none of those. It is a defect that happens to be in production.

This is the one place in the system where "match the live screen" is deliberately not followed, so it is written down twice: here and in the gap register.

The screen name is a prop, and it had to become one

It was hardcoded to "Request For Quotation".

Invisible while this component had exactly one caller, and wrong the moment it had two: Part Master opened a panel announcing itself as Request For Quotation, to sighted users and screen readers alike.

A heading that names the wrong screen is worse than no heading, because it is confidently wrong.

Where it is reached from

Two routes, on purpose:

  1. The gear in the toolbar — the deliberate way in.
  2. "Edit fields" in the filter toolbar — the way in from the place the problem is noticed. A user who wants a filter field that is not there has no way to guess the answer lives behind a button called Setup View Template at the other end of the toolbar.

That second link is omitted inside the View Setting preview, which is already there.
